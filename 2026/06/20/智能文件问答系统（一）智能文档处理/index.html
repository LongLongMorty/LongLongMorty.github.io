智能文件问答系统（一）智能文档处理

让我们通过一个完整的实战案例，展示如何将记忆系统和RAG系统有机结合，构建一个智能文档问答助手。

背景

在实际工作中，我们经常需要处理大量的技术文档、研究论文、产品手册等PDF文件。传统的文档阅读方式效率低下，难以快速定位关键信息，更无法建立知识间的关联。本案例将基于动手学大模型教程Happy-LLM的公测PDF文档Happy-LLM-0727.pdf为例，用Go语言构建一个单文档的智能问答系统。

智能文件问答系统

我们将实现以下功能：

  1. 智能文档处理：使用MinerU实现PDF到Markdown的统一转换，基于Markdown结构的智能分块策略，高效的向量化和索引构建
  2. 高级检索问答：多查询扩展（MQE）提升召回率，假设文档嵌入（HyDE）改善检索精度，上下文感知的智能问答
  3. 多层次记忆管理：工作记忆管理当前学习任务和上下文，情景记忆记录学习事件和查询历史，语义记忆存储概念知识和理解，感知记忆处理文档特征和多模态信息
  4. 个性化学习支持：基于学习历史的个性化推荐，记忆整合和选择性遗忘，学习报告生成和进度追踪

Markdown 解析、章节、分块

Document/chunk.go实现了面向 RAG（Retrieval-Augmented Generation，检索增强生成）系统的 Markdown 文档解析与切片（Chunking）工具。

简单来说，它的核心任务是：把一篇长篇的 Markdown 文章，按照结构（标题层级）切分成一小块一小块的“文本段”，并保留上下文元数据（比如这个段落属于哪个标题、占第几行、有没有表格等），以便后续喂给大模型或向量数据库。

1. 核心数据结构

代码定义了四个核心结构体，它们层层递进，构建了文档的立体模型：

  • Document：顶层文档对象。包含文档 ID、文件路径、文章标题，以及由多个 Section 组成的切片。

  • Section：章节/段落。这是解析时的基本单位。每当遇到 #、## 等标题时，代码就会切分出一个新的 Section。它记录了当前章节的标题、层级（Level）、从哪一行开始到哪一行结束（StartLine/EndLine），以及当前章节在整个目录树中的路径（Path，例如 ["第一章", "第一节", "小节A"]）。

  • Chunk：切片。这是最终输出给大模型使用的结果。如果一个 Section 的字数太长，它会被进一步切碎成多个 Chunk。

  • ChunkMetadata：切片的元数据。带上了这些元数据（如父级标题路径、是否有表格/图片），大模型在做语义检索时就能获得更精准的上下文。

2. Markdown 解析流程 (ParseMarkdown)

这是代码中最复杂的部分，采用的是状态机流式扫描（行扫描）的方式：

  1. 处理代码块（Fence）：通过 isFenceLine 检查是否进入了 ````` 或 ~~~ 包裹的代码块。如果在代码块内部，即使里面有 # 也不会被误判为标题。
  2. 提取标题与树状路径（Stack 栈的应用）：
    • 当遇到新标题时，会利用一个模拟的 stack（栈）来维护当前的目录层级。
    • 如果新标题的层级比栈顶的低（比如从 ### 回到 ##），它会把栈里所有更深层级的章节“弹出”，以此确保 section.Path 始终能准确反映当前段落的父级关系。
  3. 动态特征捕获：在结束一个章节时（finishCurrent），代码会顺便扫描这段内容里有没有 <table、|---（Markdown表格标准语法）或 ![（图片），并把 HasTable 和 HasImage 标记为 true。

3. 智能重叠切片算法 (ChunkDocument)

当要把一个长章节切分成固定大小（默认 1200 个字符）的 Chunk 时，代码实现了一个非常经典的带重叠窗口（Overlap）的滑动切片算法。

为了防止一句话在正中间被死板地切断导致大模型看不懂，它支持设置 overlapRunes（默认 160 个字符）。这意味着相邻的两个 Chunk 之间有一段文本是重复的，保证了上下文的连续性。

如果刚好到了 1200 个字，代码不会直接一刀切，而是从后往前倒查：

它会优先寻找换行符、中文句号/叹号/问号、英文句号/叹号/问号。也就是说，它会尽量让每一个 Chunk 在一个完整的句子结束处断开。

循环滑动窗口主体
  • start：当前窗口起始下标；
  • end：理论最大切割边界（start + 最大块长度）；
  • 若剩余文本撑不满一整个窗口，直接截取末尾剩余内容，循环结束。
语义断点切割（核心优化点，区别于简陋滑动分块）

不用粗暴切到 end，而是调用 findSplitPoint 在 [start, end] 内反向查找自然断句点：

示例：窗口到 512 字符，第 490 位刚好是句号，就切到 490，而不是硬切 512，保证每一块都是完整句子，召回效果大幅提升。

计算下一轮起始位置 + 死循环防护（重叠逻辑）

  1. next := cut - overlapRunes下一个窗口起点 = 当前切割位置 - 重叠字符数，实现两块尾部重复一段文本。例：当前切到 490，重叠 64 → 下一轮从 426 开始，426~490 的内容会同时存在两块里。

  2. 防卡死判断

    极端场景：

    findSplitPoint返回的 cut 和 start 几乎贴在一起（一整段无任何标点长文本），cut - overlapRunes会小于等于当前 start，窗口无法前进，死循环。

    兜底策略：直接令 next = cut，下一轮从当前切割点开始，不再重叠，强制窗口向前推进。
