智能文件问答系统（二）Embedding、持久化以及retrieve

让我们通过一个完整的实战案例，展示如何将记忆系统和RAG系统有机结合，构建一个智能文档问答助手。

背景

在实际工作中，我们经常需要处理大量的技术文档、研究论文、产品手册等PDF文件。传统的文档阅读方式效率低下，难以快速定位关键信息，更无法建立知识间的关联。本案例将基于动手学大模型教程Happy-LLM的公测PDF文档Happy-LLM-0727.pdf为例，用Go语言构建一个单文档的智能问答系统。

智能文件问答系统

我们将实现以下功能：

  1. 智能文档处理：使用MinerU实现PDF到Markdown的统一转换，基于Markdown结构的智能分块策略，高效的向量化和索引构建
  2. 高级检索问答：多查询扩展（MQE）提升召回率，假设文档嵌入（HyDE）改善检索精度，上下文感知的智能问答
  3. 多层次记忆管理：工作记忆管理当前学习任务和上下文，情景记忆记录学习事件和查询历史，语义记忆存储概念知识和理解，感知记忆处理文档特征和多模态信息
  4. 个性化学习支持：基于学习历史的个性化推荐，记忆整合和选择性遗忘，学习报告生成和进度追踪

Ark 火山方舟 Embedding

默认参数

ArkConfig 配置结构体

Ark 客户端核心结构体

互斥锁：保护 dim 维度字段并发读写

核心：顶层入口 Embed 批量向量化

核心流程：分片批处理

  1. 将输入文本按 BatchSize 切分成多个小批次；
  2. 每一批调用带重试逻辑的 embedBatchWithRetry；
  3. 拿到向量后自动记录维度；
  4. 多批次之间休眠 BatchDelay，防止触发平台限流；
  5. 全程监听 ctx，取消上下文立刻中断返回。

指数退避 + 抖动算法 backoffDuration

借鉴计算机网络退避算法

指数增长：第 1 次等 2s，第 2 次 4s，第 3 次 8s…… 上限 30s；

抖动 jitter：随机叠加 0~50% 等待时间，避免大量客户端同一时刻并发重试造成雪崩（惊群问题）；

封顶 30s，防止单次等待过长阻塞业务。

Qdrant 向量存储层

向量数据库选择的是Qdrant

核心写入：Upsert 批量插入向量切片

入参：[]EmbeddedChunk 一批带向量的文档块

完整执行流程：

  1. 空切片直接返回，无操作；
  2. 取第一条向量获取维度，空向量报错；
  3. 调用 ensureCollection 保证集合存在；
  4. 遍历所有 chunk 做校验：每条向量维度必须统一，不一致直接报错；
  5. ID 转换：chunk.ID 字符串 → uint64 数字 ID（FNV64 哈希）

核心检索：Search 向量相似度召回

入参：查询向量 +topK返回条数

流程：

  1. 空向量 / 非法topK做兜底校验；topK<=0 默认返回 5 条；
  2. 调用 Qdrant Query 向量检索接口：
    • 传入查询稠密向量
    • Limit=topK
    • WithPayload=true：带回文档元数据
    • WithVectors=false：不返回向量节省带宽
  3. 遍历召回命中结果，将 Payload 反序列化为 document.Chunk；
  4. 组装 SearchResult {Chunk, Score} 返回，Score 是余弦相似度分数。

retriever 检索模块

该模块是整套 RAG 系统检索中枢层，串联三大底层依赖：

  1. embedding：文本向量化
  2. store：Qdrant 向量库持久化存储
  3. llm：大模型能力增强检索（多查询扩展 MQE、假设文档 HyDE、RRF 融合重排）

提供四种检索模式：基础向量检索、MQE 多查询扩展检索、HyDE 假设文档检索，附带 RRF 融合重排、上下文拼接工具方法，是 RAG 召回阶段核心实现。

基础向量查询

MQE Multi-Query Expansion 多查询扩展检索

核心思路：1 个原始问题 → LLM 生成多条同义改写问题 → 每条分别向量检索 → RRF 融合多份召回结果，去重加权重排，解决单一 query 表达片面导致漏召回问题。

HyDE Hypothetical Document Embeddings 假设文档检索

核心思路：用户提问 → LLM 生成一段假想标准答案 → 用假想文档文本做向量检索。

优势：自然语言问题往往简短、特征稀疏，LLM 生成完整段落语义更丰富，向量匹配精度更高。

RRF 倒数排名融合 reciprocalRankFusion

融合多轮检索（MQE 多条 query 各自召回列表），消除不同向量检索分数尺度差异，仅靠排名位置加权打分，无需统一相似度分数，效果稳定。

检索模式 依赖 LLM 核心原理 适用场景
Retrieve 基础向量检索 否 用户问题直接向量化召回 无大模型、低延迟简单问答
RetrieveHyDE 假设文档 是 LLM 生成假想答案再检索 问题简短、语义稀疏、专业知识库
RetrieveMQE 多查询扩展 + RRF 是 多条同义 query 分别检索融合 歧义问题、多角度查询、提升召回完整度
