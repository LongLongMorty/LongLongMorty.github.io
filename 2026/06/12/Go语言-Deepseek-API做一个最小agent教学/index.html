Go语言+Deepseek API做一个最小agent教学

打算用Go做一个最小 agent，可以选择工具、执行工具、返回最终答案，用到的库是github.com/sashabaranov/go-openai，模型是deepseek v4 flash。

1.简单的 LLM API

首先我们来构建一个简单的 LLM API 完成普通对话，我采用的是OPENAI 的标准实现，刚好我最近在deepseek官网充了点米，直接接入来试试吧

目前的思路就是一问一答，historyMessages 是切片，每次用户提问、AI 回复都会 append：

  1. 初始：1 条 system 角色消息
  2. 一轮对话：新增 user + assistant 两条
  3. 对话轮次越多，切片长度线性增长，永久保留全部历史

示例：

  • 第 1 轮后：1 + 2 = 3 条
  • 第 2 轮后：1 + 4 = 5 条
  • 第 10 轮后：1 + 20 = 21 条

代码无条数限制，会无限累加，对话越多上下文越长、Token 持续上涨，最终触发超限 / 响应变慢。可以采用只保留最近 5 轮对话（10 条问答消息）+ 固定 system 提示词，超出就截断的方法来解决这个问题

完整的 Function Call 包含 4 个核心阶段。它本质上是 Observe -> Think -> Act -> Observe 循环的具象化落地：

  1. 用户提问 (User -> LLM)： 用户要求计算或查询某事。
  2. 模型思考并决定调用 (LLM -> Go)： 模型发现自己算不出来，返回一个结构化的 Tool Call 决策（在 OpenAI 协议中称为 assistant 角色的工具请求）。
  3. 本地执行工具 (Go 本地)： 你的 Go 代码拦截到这个 JSON，调用本地的函数（如计算器），拿到真实的计算结果（字符串）。
  4. 回填结果并二次推理 (Go -> LLM)： 你的 Go 代码把工具执行结果打包成一个特殊的角色（OpenAI 协议中叫 tool 或传统模拟成 user 反馈），再次丢给大模型。大模型拿到结果后，组织语言回答用户。

4. 执行工具，并把工具结果喂回模型

5.给 agent loop 加最大步数、超时和错误处理

在真实的工业级 Agent 落地（如在生产环境运行的自动化运维或终端 Agent）中，如果让 Agent 在一个没有任何约束的 for 循环中无限狂奔，是非常危险的。大模型一旦陷入“幻觉”或遇到预期外的工具报错，极易引发死循环（Infinite Loop），这不仅会瞬间烧光你的 API 余额，甚至可能对本地系统造成毁灭性破坏。

因此，一个合格的 Agent 框架，必须死死守住底层防线的“三驾马车”：最大步数限制（Max Iterations）、超时控制（Timeout） 以及 鲁棒的错误处理（Error Catching）。

运行这段代码时，会观察到Agent 自我纠错（Self-Correction）过程。

  1. Step 1： 用户要求读一个不存在的假文件 nginx_fake.conf。DeepSeek 拆解任务，第一步决定去调用 read_file。
  2. 本地 Act 报错： 我们的 safeExecuteTool 敏锐地抓到了底层的 os.ReadFile 报错（文件不存在），我们的代码没有挂掉，而是把 os.ReadFile error: ... 不存在 变成文本反向喂回给了大模型。
  3. Step 2（自适应调整）： 大模型接收到报错信息（Observe），它的大脑（Think）会恍然大悟：“噢，原来文件不存在，我的第一步策略失败了，我没办法拿到行数再乘以 2 了。” 于是它会及时终止后续的 calculator 任务，自动在这一步收敛，直接输出 tool_name: "none"，并在 final_thought 里向人类报告：“对不起老板，我刚才尝试去读了文件，但系统反馈文件不存在，无法完成后续计算，请确认路径。”
